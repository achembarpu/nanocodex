# Deployment patterns

Nanocodex does not impose an app-server protocol. Deploy the same owned session
inside the platform lifecycle you already use, and keep credentials, durable
state, clients, and sandbox policy in that application.

## Browser and Node

- [React/Vite](https://github.com/gakonst/nanocodex/tree/master/examples/react-vite)
  runs the browser WASM agent in a module Worker and renders ordered events.
- [Browser CDN](https://github.com/gakonst/nanocodex/tree/master/examples/browser-cdn)
  is one static HTML file with no install or build step.
- [Node](https://github.com/gakonst/nanocodex/tree/master/examples/node) uses a
  Node WebSocket host and local guarded workspace.

## Durable platform owners

- [Vercel Workflows](https://github.com/gakonst/nanocodex/tree/master/examples/vercel-workflows)
  models the agent as a durable Workflow actor, retains replayable state, owns a
  persistent Vercel Sandbox, synchronizes native WebSocket clients, and attaches
  a wterm operator shell to the same workspace.
- [Cloudflare Workers](https://github.com/gakonst/nanocodex/tree/master/examples/cloudflare-workers)
  uses a SQLite-backed Durable Object, Sandbox container, R2-backed workspace,
  and hibernation-safe session recovery.
- [Cloudflare fetch + MCP](https://github.com/gakonst/nanocodex/tree/master/examples/cloudflare-fetch-mcp)
  demonstrates an authenticated Rust/WASM fetch endpoint, QuickJS Code Mode,
  deferred MCP, and a serialized Durable Object payment owner.
- [Rivet Actors](https://github.com/gakonst/nanocodex/tree/master/examples/rivet-actors)
  keeps the harness in a durable SQLite-backed Actor with an actor-owned AgentOS
  sandbox.
- [exe.dev](https://github.com/gakonst/nanocodex/tree/master/examples/exe-dev)
  demonstrates both a private retained agent inside a persistent VM and an
  external agent that treats the VM as a caller-owned tool.

## Design checklist

1. Give one durable platform owner exclusive access to each live agent.
2. Persist snapshots only after completed turns, in an application-versioned
   envelope containing the policy needed to reconstruct the agent.
3. Keep event delivery independent from result completion; clients may reconnect
   without becoming owners of conversation history.
4. Create fresh agent-relative tools for spawns and forks.
5. Make sandbox lifecycle, workspace durability, egress, secrets, and cleanup
   explicit.
6. Close descendant task trees and tool processes before stopping the root.

These examples are runnable integration proofs, not portability guarantees for
platform APIs. Pin versions and test the recovery semantics that matter to your
product.

## Vercel Workflow, Sandbox, and wterm

The Vercel example keeps three lifecycles deliberately separate:

- Workflow retains the Nanocodex snapshot and replayable typed event stream;
- one named persistent Vercel Sandbox retains `/workspace`; and
- `@wterm/react` renders an operator PTY created by `Sandbox.openInteractive()`.

The terminal uses Vercel's controller protocol directly: the browser sends one
JSON start frame for `bash -l`, binary UTF-8 input, JSON resize frames, and
receives binary output plus text exit controls. The attachment route requires a
separate bearer secret before it asks Vercel for a short-lived URL and token.
Those credentials never enter Workflow history.

Agent history survives Workflow replay and files survive Sandbox snapshots. The
interactive shell is ephemeral per attachment and must request a fresh token
after disconnect; persistent files do not imply PTY process continuity. This
operator terminal is therefore not a second agent protocol and does not require
an AI SDK Harness adapter. See the [implementation and security notes](https://github.com/gakonst/nanocodex/tree/master/examples/vercel-workflows#workspace-terminal-wterm--vercel-sandbox).

## Recovery boundary

Persist only complete checkpoints and reconstruct one owner before accepting
new prompts. A Durable Object, Workflow, or Actor may replay its own execution,
but model requests and tool effects are not automatically replay-safe platform
steps. Keep Nanocodex's owned driver live behind the actor boundary and use the
application snapshot as the restart handoff. Clients should reconnect to that
owner rather than replaying prior messages, response IDs, or tool results.

Hosted Responses proxies should authorize the user before upgrading the socket,
scope credentials to the thread, and keep diagnostics off contractual stdout or
client event streams. A sandbox's persistent filesystem and the session
snapshot need coordinated retention but remain separate data: restoring one
does not prove the other is current.
