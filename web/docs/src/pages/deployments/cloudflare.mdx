# Cloudflare Durable Objects

The Cloudflare example is one concrete adapter. One SQLite-backed Durable
Object owns one Nanocodex session, its Rust/WASM driver, OpenAI socket, client
sockets, and opaque durability journal. A separate Cloudflare Sandbox owns
Linux execution; R2 backs its per-session workspace.

```text
client -> Worker router -> NanocodexSession Durable Object
                          |- Rust/WASM agent
                          |- SQLite journal batches
                          |- hibernatable client sockets
                          `- Sandbox DO -> container -> R2 workspace
```

## Adopt the pattern

```sh
npm install nanocodex
```

Import `nanocodex/host` inside your Durable Object and give that object
exclusive ownership of one live agent. The concrete
[Cloudflare reference consumer](https://github.com/gakonst/nanocodex/tree/master/services/managed)
shows the SQLite host store, Sandbox tools, R2 workspace, client routing, and
API-key or ChatGPT credential owners. It is reference application code, not a
second package or a source-build prerequisite for the SDK.

## Durable store

The object maps the JavaScript durability host interface onto two SQLite
tables: journal revisions and opaque journal batches. The host implements load
plus atomic compare-and-append. It does not interpret model or tool state.
Rust/WASM owns operation deduplication, checkpoint reconstruction, committed
step-output replay, and ambiguous unsafe-tool classification.

```ts
import { Agent } from "nanocodex/host";

const agent = await Agent.create({
  transport,
  module: nanocodexWasm,
  sessionId,
  durability: this.#durabilityStore(),
  durabilityId: sessionId,
  tools: [...sandboxTools],
});
```

That SQLite store is why the restart claim is durable. An in-memory store would
not survive object eviction.

This durable root deliberately omits `Subagents.create()`. The subagent
registry and child drivers belong to one live runtime and cannot be reconstructed
from the root journal after Durable Object eviction. The SDK rejects an attached
execution policy before spawning a child, and a completed tool result is not
replayed when its handler is absent from the recovered runtime; neither boundary
can emit a ghost child ID.

## Hibernation boundary

An outbound OpenAI WebSocket keeps the object active. The example closes the
agent after an idle alarm, while Cloudflare keeps accepted client sockets
hibernatable. The next client command reconstructs the agent from the SQLite
journal. Clients resume their event projection; they do not send prior
messages, response IDs, or tool results back to Rust.

The session journal and R2 workspace have separate lifetimes. Restoring files
does not prove that a model/tool step committed, and restoring the journal does
not recreate a stopped container process.

## Worker constraints

Cloudflare Workers reject dynamic `eval`. This example selects the CSP-safe
direct-tool mode; it does not pretend QuickJS or browser OPFS exists in every
Worker. The separate fetch + MCP example shows QuickJS Code Mode as another
explicit composition.

Credentials, router authorization, session capabilities, R2 prefixes, Sandbox
policy, and hosted web tools remain application code. This example does not
define a generic Durable Object or serverless agent protocol.
